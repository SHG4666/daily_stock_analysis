# 原图八形态与扩展突破自动选股

每日Actions默认使用`bottom_reversal`（规则版本`6.0-base-volume-breakout`）：底部反转、企稳突破及上涨中继，四条分支都要求**当日放量上涨且实际换手率提高**。`bottom_reversal`和结果字段同名是保留兼容的历史标识；原底部反弹、探底回升及上涨中继分支保留，新增企稳突破复用已有“均线上方放量突破”检测器，覆盖横盘企稳后的首段启动，不要求当前仍下跌或已完成上涨后4–12日整理。用户原图八种形态仍保留在`all_patterns`兼容模式（`2.0-volume-breakout`），其中“均线上方放量突破”检测逻辑与每日模式共享，不凭股票名称或形态标签放行。输出是“技术形态候选”，不是上涨概率、保证收益或下单指令。每个候选附名称、代码、实际行情日期和条件证据，供人工看K线复核。版本与完整参数快照写入筛选JSON，HTML显示版本。

## 每日底部反弹标准

在这些硬条件之上可启用[每日复盘与持续学习](selection-learning.md)：保存完整市场快照和原排序，后续交易日对照实际推荐表现；只有充分验证后才改变候选之间的优先级，不自动放宽本页硬条件。

以下为两条**底部反转分支**的初始门槛。它们要求长期下跌，位置和此前涨幅按分支判断；新增上涨中继分支另见下文，以明确的上升/整理结构代替下跌背景。所有分支共用当日阳线涨幅≥2%、量比≥1.8、收盘位于日内振幅上方35%、实际换手率提升的硬条件；没有收益回测证明优于旧策略。不固定推荐数量，不给个股预留名额。

| 条件 | 门槛（交易日） |
| --- | --- |
| 长期下跌 | 当日前60根K线首尾收盘下跌至少15%；昨日MA20较40日前下降至少8%，避免把单日暴跌当长期下跌 |
| 仍处底部 | 原反弹分支当日收盘不超过此前60日最低价的1.2倍；新增分支见下文 |
| 当天上涨 | 收阳线，较昨日收盘上涨至少2% |
| 当天放量 | 成交量至少为此前20日平均的1.8倍，分母排除当日 |
| 收盘质量 | 收盘位于日内振幅上方35%；原反弹分支此前5日累计上涨不超过10% |
| 换手率提高 | 当天实际换手率至少为昨日的1.2倍、此前5日均值的1.5倍 |

### 新增：探底回升放量突破

用户2026-10-26图片显示持续下跌后探底、短线回升、再放量上攻的结构。图片没有股票代码、日期和均线周期，不能据此复算原股；以下是可复核的工程定义，使用MA5/10/20，不把截图颜色或“买”标记当成证据。

原分支保留。新增分支仅在以下条件**全部成立**时允许距低点从20%扩展到30%、此前5日涨幅从10%扩展到15%；其他共同硬条件不变：

- 截至昨日的60日最低价，最近一次出现于目标日前2–10个交易日；当日最低价不再跌破它。
- 最近5个交易日（含目标日）MA5由不高于MA10穿到上方，目标日仍在其上；MA5和MA10当天均抬升。
- 收盘站上目标日MA5、MA10、MA20，并严格突破此前5日最高价；阻力窗口不含当日。
- 收盘距上述低点不超过30%，截至昨日的5日累计涨幅不超过15%，防止过度追涨。

同股只输出一个信号：按原底部反转、上涨中继、企稳突破的顺序接收首个完整合格分支，不重复计数或加分。筛选JSON记录逐项结构检查、低点日期/距今交易日和突破价；报告保留雪球链接，不自绘曲线。新版本和完整参数摘要改变后，持续学习不会沿用旧规则下的已升级排序，需要重新积累新规则验证样本；旧推荐复盘记录保留。

### 新增：上涨后缩量回踩再突破

用户第二张图片显示“上涨—整理回踩—再突破”。它已经处于上升阶段，与前两条底部反转分支并列，不再要求当前60日下跌或MA20持续下降。截图没有代码、日期及价格均线周期，以下明确使用MA5/10/20/60定义结构，图片中的“K/筹”等标记不作为信号。

1. 在目标日前13根K线中找最近一次最高价，之后必须有4–12个完整整理交易日。该前高也必须为其前20个交易日至前高当日窗口的最高价；窗口低点先于前高，低点至前高上涨15%–50%，确保先上涨再整理。
2. 截至昨日MA20在MA60之上，两线均较5个交易日前抬升。整理期间至少一次最低价到MA10上方2%以内，各日收盘不低于当日MA20的97%；前高至整理最低价回调2%–12%。
3. 整理均量不超过上涨末5日均量的80%，防止放量下跌被当作正常整理。
4. 目标日收盘突破前高0.5%–8%，站上MA5/10/20/60且MA5/10当天抬升；量至少为整理均量1.5倍。仍必须同时满足共用的阳线涨幅≥2%、此前20日量比≥1.8和强收盘，不能用整理期低量替代共用量比。
5. 收盘较MA20乖离不超过25%、距上述启动低点涨幅不超过60%、正向开盘跳空不超过5%；真实换手率仍须较昨日至少1.2倍、此前5日均值至少1.5倍。模型看空/卖出者仍不推荐。

前高、整理和均量基准都排除目标日；不使用之后的涨幅反推当时信号。当天未突破、整理不足、深跌失守支撑、整理不缩量或突破过高者不靠该分支入选；不追补几天前的突破。JSON的`continuation`含条件检查、前高日期、整理长度、涨幅/回调幅度和缩量比；完整参数嵌入`parameters.bottom_reversal.trend_continuation`参与学习规则摘要。没有新增配置项或通知渠道。

### 新增每日入口：企稳后的均线上方放量突破

用户确认参考是一心堂002727“2026年9月起底、10月上涨”的区间。9月没有满足当日放量门槛；10月首段上涨还没有形成中继分支要求的整理结构，5.0每日模式因此遗漏。6.0把此前只在兼容模式中具备候选资格的“均线上方放量突破”接入同一每日量价及真实换手率路径，检测器和原有门槛完全复用，未为某只股票写特例。

- 前收及今开高于昨日MA5/10/20/30，今收高于今日四线；MA5此前已在MA10上方，今天两线均向上。
- 昨日四线最大/最小比值不超过1.05，昨日MA20较其3个交易日前不下降，识别企稳而非仅靠当天大阳修复下跌均线。
- 当天阳线实体及较昨收涨幅均至少3%；量至少为此前20日均量2倍；收盘突破此前20日最高价至少0.5%，收盘位于日振幅上方25%、实体占振幅至少50%。
- MA20乖离≤15%、含当日5日涨幅≤20%、正向开盘跳空≤5%，限制追涨。仍须通过每日共同阳线/量价门槛及真实换手率≥昨日至少1.2倍、前5日均值至少1.5倍；模型看空/卖出者仍不进入推荐。

同一检测器返回结果写入`bottom_reversal.volume_breakout`；完整参数嵌入`parameters.bottom_reversal.volume_breakout`，与旧`parameters.volume_breakout`一致并参与学习规则摘要。其余原图八形态仍不能替代每日资格，不改本地/手动普通分析。

冻结真实样本核对：一心堂2026-10-14收盘12.46元，突破前20日高点11.98元，量比5.37、实际换手率8.33%（为昨日1.76倍、此前5日均值2.95倍），在新每日入口进入技术候选。10月12日因突破前MA20仍下降而保守排除，10月13日实体不足且换手率未较昨日提高，未倒填信号。这里只证明历史结构资格，不是当时曾发送推荐，也不是用后续上涨证明规则有收益。筛选后仍竞争前10名并接受模型否决，不保证指定股票每天入选。

背景窗口不含当日，确认使用目标日完整K线；本版优先实现当天触发，不追补前几天放量但今天不符合条件的股票。复用腾讯前复权日K同日缓存中的第8项实际百分数换手率（如3.74表示3.74%，不同于第6项成交量和第9项成交额）；参考[腾讯原始日K响应](https://proxy.finance.qq.com/ifzqgtimg/appstock/app/newfqkline/get?param=sz002727,day,,,240,qfq)。逐日精确对齐最后6个交易日，不前向填充、不用量比或当前流通股本估算历史换手率。旧缓存只有六列时仍供传统形态使用，不能通过换手率核验。该功能不新增网络接口，OHLCV与换手率来自同一响应/缓存；缺数不切换不同口径数据源。

数据异常明确计入`turnover_data`。除整体日期核验覆盖外，所有量价初筛通过者的换手率有效覆盖也必须达到`PATTERN_SCREEN_MIN_COVERAGE`；覆盖不足时停止后续自动分析，不能把数据失败写成“无候选”。无量价初筛通过者时不读取换手率序列。通过者先按“当日换手率/此前5日均值”降序，再按量比、代码排列，最多交给AI分析10只。

模型分析后再作确定性否决：`trend_prediction`明确看空/空头（包括英文）或`decision_type=sell`、操作建议为减仓/卖出者，从每日推荐中剔除。不是靠Prompt要求模型自行遵守；单股、聚合、本地日报、合并通知和飞书文档共用过滤后的结果。日志记录被否决代码和原因；分析成功但全部被否决时不发送个股，也不补入其他股票凑数，大盘复盘继续。该否决仅用于工作流设置`PATTERN_SCREEN_ACTIVE=true`的自动选股，普通手动/API分析仍允许如实报告看空；不会把分析看空改写成看多。

## 每日流程

`.github/workflows/00-daily-analysis.yml` 计划于北京时间周一至周五16:00运行。GitHub定时触发可能延迟或漏跑，启用状态和手动运行成功不等于定时触发已经验收；需确认Actions中出现`event=schedule`的运行记录。16:00是计划启动时间：任务还需要筛选及模型分析，实际消息到达会晚于启动；更改cron不能保证16:00准点收到。已移除工作流启动时额外0–60秒随机等待。计划按工作日触发，由交易日检查跳过节假日；此时间只影响GitHub Actions，不改变本地`SCHEDULE_TIME`配置。

漏跑时可在Actions的“每日股票分析”中选择main分支、full模式手动补跑；这会执行当天筛选、分析并向已有通知渠道发送结果。收盘后、最新完整交易日和有效覆盖检查仍然适用，不用`force_run`绕过日期核验。定时触发的限制见[GitHub官方说明](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule)。

### 定时延迟跨午夜

若GitHub的`schedule`事件延迟至北京时间次日00:00（含）至09:00（不含），且最近完整行情日恰为上一自然日，交易日历明确确认上一日已经收盘，则继续处理上一完整交易日。周五延迟至周六也适用；手动触发、本地定时、盘中、跨多日、上一日休市或日历无法确定时，不会借此放行旧候选。正常休市仍正常跳过，不补跑多日前的结果。

筛选JSON及GitHub步骤输出记录`as_of`、`delayed_schedule`，JSON另存实际`generated_at`。仅延迟分支向`main.py`传入`--completed-session YYYY-MM-DD`；主入口重新验证事件、时间窗口和交易日，不使用全局`--force-run`。这是当次运行参数，无需新增Repository Variable或修改持久配置，不能当作任意历史回测入口。

延迟分析的日K下载指定截止日并截断供应商多返回的日期；数据库上下文和Agent历史工具沿用截止日，禁用实时补K、实时行情和无法按日限界的筹码工具。缺目标日数据时停止该股，不能改为仅凭新闻继续。报告区分“行情截至上一交易日”和“实际生成时间”；新闻、公告及其他基本面查询仍到实际生成时刻，因此不是历史回测。

full模式先生成A股大盘复盘，再分析个股，减少处理期间跨入开盘窗口的风险。大盘行情抓取前后都核验09:00边界，越界时明确失败而不把新行情标成昨日；仅大盘模式失败会返回非零。延迟分支只复盘A股，海外市场跳过；正常分支沿用原市场配置。聚合、单股、合并通知及飞书文档均显示行情日；候选页面也显示延迟说明和实际生成时间。

跨午夜处理不改变上文的定时计划、通知路由及并发组，没有增加自动重跑或第二套定时器。每日飞书股票/大盘报告另外采用[跨Actions发送凭证](daily-delivery.md)：按行情日与目标分别记账，已送达自动跳过，部分或未知结果需人工确认；`force_run`不会放开重发。本修复不自动补发此前失败的任务，验收不发送真实消息。回滚可revert对应修复，无配置或数据库迁移。

每日流程：

1. 优先用腾讯沪深京A股列表及批量报价获取当前名称、开盘、收盘和成交额；列表分页总数、去重、证券市场/代码、逐股目标交易日及15:00后时间戳全部核验。主源任一分页/报价缺失、旧日期或请求失败时，丢弃整批主源结果，切换原新浪 `hs_a` 完整列表，报告注明实际采用的来源；不拼接两家的残缺结果。两源都失败则停止。列表和批量报价的超时/连接错误仅在1秒退避后重试一次；HTTP、解析和完整性错误不在原源重试，腾讯每股日K请求不扩增重试预算。详见[数据源选择与切换](market-data-sources.md)。
2. 排除ST/名称缺失、停牌/无报价、非阳线、当日成交额不足2000万元。底部模式还利用列表已提供的当日涨幅提前排除不足2%的股票，减少日K下载；通过后仍用完整日K再次确认涨幅，缺报价涨幅时不跳过核验。
3. 对其余股票下载240根腾讯前复权日K；第6项按成交量处理，不用它冒充成交额。只接受 `qfqday`，不拼接未复权实时价，也不以未复权 `day` 数组静默降级。
4. 最新日K必须等于当前已完成的交易日，至少120根、无重复日期、价格有效、量能有效；最新价格还需与当日报价一致。
5. 默认按上述四分支标准和实际换手率核验。仅`all_patterns`兼容模式按原八形态研究计数、量比排序。默认最多10只进入AI分析，模型否决者不推送，沿用既有通知渠道。
6. 无候选时，full模式只做大盘复盘，stocks-only模式跳过分析。查询未完成或有效覆盖不足90%时停止；不会回退600519等旧自选股。

候选池只覆盖本次运行的环境变量，原有 `STOCK_LIST` 持久配置保留。技术筛选报告位于 Actions 的 `analysis-reports-*` artifact 中的 `reports/pattern_screen/report.html`；JSON和股票代码文件为审计/下游支持。报告内点击股票名称可直接打开第三方行情；AI文字报告中的A股名称也可点击，沿用原通知流程。

## 最新披露股东户数

候选HTML和当次生成的文字报告在数据可用时显示“最新披露股东户数”，同时标出统计截止日、公告日和东方财富来源。它是公开披露的股东账户户数，不是当前实时人数，也不是前十大股东数量；不根据户均持股或其他指标推算。

数据取自[东方财富股东户数](https://data.eastmoney.com/gdhs/)，使用公开数据接口的`RPT_HOLDERNUM_DET`，按股票代码与本次日期过滤，再按统计截止日、公告日倒序取最新披露。客户端同时校验代码、正整数户数及`统计截止日 <= 公告日 <= 查询日`。历史重放不会引用查询日之后公布的数据。

户数独立于形态检测和原有基本面bundle查询。仅为形态候选补充，最多4个并发，补充阶段30秒预算，之后取消未开始请求并有限等待正在进行的请求；单请求连接/读取超时为3/5秒。分析阶段复用相同provider，在原基本面开关关闭或bundle失败时仍可取得户数。成功结果在`data/shareholder_count_cache/`缓存一小时，同一runner中的筛选脚本和分析进程可复用；失败不持久缓存。数据缺失、超时或校验失败时省略该行，不影响筛选覆盖结论、名单顺序、AI分析和通知发送。

显示字段直接来自校验后的披露数据，不让模型生成户数。候选JSON保留完整披露元数据；分析报告沿用运行时基本面上下文字段，不新增数据库表、配置项或历史API字段。旧报告不会自动补写户数。中英文文字报告使用同一数据、对应语言标签；本专题无英文副本。

`PATTERN_SCREEN_*` 参数属于独立CLI和GitHub Repository Variables，刻意不在Web设置页展示；Web设置保存不能修改GitHub的每日工作流参数。

日K同日缓存供重跑使用；新交易日重拉完整窗口，避免前复权因子变化后拼接错误。休市正常跳过，不做个股/大盘分析；盘中手动筛选返回2，不会把前一交易日信号当作今天新信号，`force_run` 也不放宽此日期检查。market-only模式沿用原有大盘流程，不经过此筛选入口。

同一交易日已收盘时，腾讯指定截止日的历史请求可能仍不包含当日日K。因此这一窗口读取同源的最新前复权窗口，再严格截取至目标日；历史日期和跨午夜冻结日期继续显式指定截止日。任何响应都不能带入目标日之后的数据，也不能以未复权报价补造一根K线。缓存除标注日期之外还要核对实际最新日，过期内容必须重抓；返回仍缺目标日时不缓存，继续计入覆盖缺口并保留停止条件。

## 八形态的初始检测条件

阈值是可复核的实现假设，没有经过收益回测。成交量基准使用此前20个交易日，不包含当天；突破阻力与弧形拟合也不包含当天。只有最新一天的确认信号进入候选。

| 形态 | 检测近似 |
| --- | --- |
| 老鸭头 | 前期MA5/10曾上穿MA30，形成至少12%上涨，再缩量回调5–20日、幅度5%–20%，MA30继续上升且回调逐日未明显跌破它；今天MA5重新上穿MA10、阳线、量比≥1.3 |
| 黄金坑 | 25日平台振幅≤18%，随后20日内下探平台中位价8%–30%；今天阳线收复MA20或平台下沿、从坑底反弹≥8%、量比≥1.3 |
| 空中加油 | 先有实体≥5%、量≥此前20日均量1.5倍的大阳，随后10–20交易日（原图2–4周）缩量小K线整理、振幅≤12%、不跌破该阳线开盘1%以上且多数日位于MA20上方；今天放量突破整理与起始大阳的最高价 |
| 底部红三兵 | 下跌或低位背景中连续三阳，实体≥0.8%、占日振幅一半以上、上影较短，收盘递升，后两日开盘在前一实体内 |
| 杯柄形态 | 60/90/120/150日U形杯身，杯深12%–35%、两杯沿相差≤8%、低位持续；5/10/15/20日缩量浅柄回调3%–12%；今天量比≥1.3并突破杯沿 |
| 一阳穿多线 | 昨日MA5/10/20/30离散≤5%，今天开盘在线下、收盘在四线上，阳线实体≥3%、量比≥1.5且接近当日高点 |
| 多方炮 | 两阳夹缩量小阴，第一与第三阳实体≥2%，中间阴线不破坏第一阳主体；第三阳收盘突破第一阳最高价、量≥第一阳1.2倍 |
| 圆弧底 | 60/90/120日平滑U形拟合R²≥0.6，底点处于窗口20%–65%、回落12%–50%、低价区持续≥10日、右侧收复≥80%；今天量比≥1.3并突破左侧阻力 |

杯柄和圆弧底会存在形态识别误差，需要人工看图。形态名称不证明“主力吸筹”“洗盘”，也不包含未来盈利判断。近期停牌导致窗口内无量或数据源缺前复权数组时，可能被保守排除，报告会统计原因。满120根且最新日期一致不保证上市以来历史完全无缺口。

## 扩展：均线上方放量突破

此规则补充“已经在线上，再放量突破”的短期走势，独立于原“一阳穿多线”；原八种检测条件不变。所有条件同时满足才产生信号，没有个股代码白名单。

| 条件 | 初始门槛 |
| --- | --- |
| 站线 | 前收、今开均高于昨日MA5/10/20/30，今收高于当日四线 |
| 短线方向 | 昨日MA5>MA10；当日MA5、MA10均较昨日上升 |
| 突破前背景 | 昨日MA20不低于3个交易日前；昨日四均线离散不超过5% |
| 实体与涨幅 | 阳线实体相对开盘至少3%，收盘较前收上涨至少3% |
| 放量 | 当日成交量至少为此前20日均量的2倍，分母排除当日 |
| 有效突破 | 收盘至少高于此前20日最高价0.5%，阻力窗口排除当日 |
| K线质量 | 收盘位于当日振幅上方25%，阳线实体至少占全天振幅50% |
| 位置约束 | 收盘偏离当日MA20不超过15%；含当日的5交易日累计涨幅不超过20%；正向开盘跳空不超过5% |

趋势背景、阻力和量能基准均不使用未来数据，确认只使用目标日已完成的K线。报告保留突破前高点、突破幅度、量比、MA20乖离及5日涨幅等证据。满足这些门槛不表示长期多头趋势已经确立，也不证明具有收益优势。

固定历史样本：一心堂2026-10-14收盘12.46元，高于此前20日最高11.98元约4.01%，量比5.37，命中该扩展；2026-10-13未有效突破且实体较弱，不命中；2026-10-12虽放量突破，但突破前MA20三日仍下降约0.37%，此保守版本不收录。10月14日的MA20乖离约14.01%，已接近15%上限，不能把“被纳入候选”描述成低风险或确定性上涨。

## 持续优化的样本复算

每次改规则先固定门槛，再用成功样本、未命中样本与反例对照；不得通过个股代码强行入选。离线工具不联网、不调用模型、不发送通知，也不自动改参数。它记录规则版本、检测器及输入CSV的SHA256、参数快照、目标日截断范围、新旧形态、每项条件真假和证据，便于以后比较遗漏与新增。

```bash
python scripts/review_pattern_cases.py \
  --manifest tests/fixtures/patterns/volume_breakout_cases.json \
  --output-dir reports/pattern_review
```

manifest格式如下，CSV路径相对于manifest；`code`和`name`仅作为报告标签，`expected_extension`可省略。同一代码和目标日不能重复。

```json
{"cases":[{"code":"002727","name":"一心堂","csv":"yxt_002727_20261014.csv","as_of":"2026-10-14","expected_extension":true}]}
```

输出`review.json`、`review.csv`、`review.md`。退出0表示数据有效且已设期望均一致，1表示期望不符，2表示manifest/数据/输出错误；错误案例明确显示原因，不能当作“未命中”。指定日期之后的K线先截断，不会影响历史判断。`include_extensions=False`仅用于原八类对照，不是每日任务的回退开关。当前工具比较的是规则样本，不计算收益，也不代表全市场回测；若只有部分股票历史，不应把样本排名描述成当时全市场前10名。

## GitHub Variables与回滚

| 参数 | 默认值 | 含义 |
| --- | --- | --- |
| PATTERN_SCREEN_ENABLED | true | 每日工作流启用；设false恢复原STOCK_LIST分析 |

| PATTERN_SCREEN_WORKERS | 4 | 日K请求并发，范围1–8 |

所有请求设置连接/读取超时。筛选预算到期取消未开始请求，有限等待正在进行的请求结束，写入不完整报告并停止自动分析。股票范围列表不使用静态索引作为“全市场”兜底。新上市不足120根属于明确排除项，旧行情、无量/坏价格和抓取失败计入覆盖缺口。

新策略完整回滚可revert对应PR，无数据库或持久自选股迁移；只恢复旧形态可设置Repository Variable `PATTERN_SCREEN_PROFILE=all_patterns`。严格门槛可能导致少选或零选，换手率来源不可用时会阻止分析，未以缺数据为由放宽条件；未执行真实模型调用或飞书补发验收。中文专题承载此次定制变化，无对应英文专题，英文首页不改。

中文专题文档作为本次用户定制规则的唯一说明；英文首页不变，因为既有功能入口和README定位不变。若后续推广为通用发布功能，应增加对应英文专题。
