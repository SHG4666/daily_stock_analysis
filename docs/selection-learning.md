# 每日选股复盘与持续学习

功能默认接入原每日 Actions，不新增第二个定时器，不自动下单，也不让大模型改写选股代码。日常流程是：保存事前市场与选股记录 → 后续交易日核验 → 与原排序和市场对照 → 满足门槛才升级排序 → 退化时回滚。

## 每天记录什么

- 与每日筛选共用腾讯优先、失败时整批切换新浪的全市场列表入口，再批量读取腾讯逐股收盘快照，按股票代码与行情时间戳确认属于目标交易日、15:00之后；成交量和成交额复用既有腾讯单位解析器。缺少、过期、盘中、停牌行情不填零、不前向填充，分别进入覆盖缺口。
- 全市场同时保留上涨与未上涨股票，而非只挑已经上涨的成功样本。研究对照范围为当日非ST、成交额至少2000万元、有成交的股票；该范围随日期保存，不能用今天的名单重建过去的市场。
- 记录原始34个等技术候选的完整基线顺序、当时规则版本/参数、技术入选、模型接受/否决、排序策略及其摘要。这里的34只是一次运行例子，候选数量没有固定值。
- “实际推送”只接受同一行情日、同一运行ID的模型审计及完整飞书ACK；候选文件或模型成功日志不等于发送成功。失败/不确定的回执不计入实际推荐样本，同日重跑不改写已有成功记录。
- 只存量价与研究记录，不把API密钥、Webhook地址、模型Prompt或新闻正文放入学习档案。

## 次日如何判断

使用交易日历精确定位第1、3、5、20个后续交易日。周五的次日是下一个开市日，周末不算失败；若周一行情缺失，不能用周二冒充周一。未到期记pending，已到期但无行情记unavailable，不进入上涨比例分母。

未来交易日超出已公布日历时，保持pending且不猜测截止日期；日历边界不会阻断已经到期的核验。下一开市日尚不能确认时，不从旧日报引入首次记录。实际观测日期本身超出日历则暂停学习，等待交易日历依赖更新，原选股继续运行。

报告分别展示技术入选、实际推送、模型否决三个分组的上涨比例、平均涨跌、样本数，以及同期市场对照；JSON保留逐股结果与最大不利波动。用既有 `BacktestEngine` 对同源前收基准串联的涨跌幅指数进行方向诊断。

**这不是可成交收益回测。** 信号在收盘后才产生，不能假定当日收盘买入；未模拟滑点、费用、现金分红、涨跌停成交和A股T+1卖出限制。报告称“上涨比例/平均涨跌”，不能把它说成真实交易胜率或投资收益。停牌、退市或缺数据会影响可评估样本，报告保留缺口而非制造收益。

## 如何寻找上涨前特征

赢家定义为随后5个交易日累计涨幅至少5%。只读取该段上涨开始之前已经保存的特征，研究成交量相对此前20日均量、实际换手率相对昨日、此前5日涨跌、当日涨幅和收盘在振幅中的位置。

第一版限定六个可解释的假设：收盘偏强、温和上涨收高、换手率提高、放量、量与换手同步提高、此前横盘或回落后放量。每个假设都列符合组与未符合对照组的样本数、随后赢家比例；缺特征不归入反例。样本不足30只不计算提升。报告还列出最近上涨样本及上涨前观察日，链接继续使用雪球，不绘制股票曲线。这些是相关性观察，不证明上涨原因。

## 自动升级的边界

自动调整仅改变**已经通过各选股分支硬条件的候选之间的排序**（底部反转、企稳突破或上涨中继），不添加未达标股票，不取消实际换手率核验，不取消模型看空/减仓/卖出否决，也不为凑数量放宽条件。完整参数摘要包括上涨中继及企稳突破条件；规则版本或参数改变后重新验证，保留旧推荐复盘。

1. 至少积累90个已经成熟、有候选的交易日。持久档案最多保留120个观测交易日，训练只用最近120个市场交易日且硬条件版本和参数摘要一致的数据；不会拿几千只同日股票冒充几千个独立交易日。
2. 按时间切分：训练段选择一个特征排序，25日验证段和25日最终留出段分别检查。分割边界留出5个交易日，避免5日赢家标签跨入下一段。参考[时间序列交叉验证](https://scikit-learn.org/stable/modules/generated/sklearn.model_selection.TimeSeriesSplit.html)和[数据泄漏防范](https://scikit-learn.org/stable/common_pitfalls.html#data-leakage)的原则；实现使用固定有限规则，不引入新的机器学习依赖。
3. 在当时保存的完整候选池上，分别计算原排序和候选排序前N只的**次日**表现，不假设未选股票已经通过历史模型否决。每段至少20个可完整配对的日期，要求平均提升至少0.2个百分点、上涨比例提升至少5个百分点、最差日期不明显恶化。按5日分块比较均值与波动，仍不把这些门槛当统计证明或未来收益保证。
4. 只有周五尝试升级；一次验证后至少等待20个新的市场交易日，限制反复使用相同数据调参。没有改善或样本不足时保留原换手率提升排序。
5. 升级后持续对照原排序；20个可评估日期的平均表现落后0.2个百分点以上或上涨比例落后10个百分点以上时回滚。历史有缺口或分支硬条件变更时也回到原排序并重新验证。

初次启用通常需要数月才满足自动升级门槛。在此之前仍每天建档、复盘和发现特征，不伪造“已经自我优化成功”。自动策略ID、验证分段日期、样本数与摘要均可审计。

## 跨Actions保存与恢复

权威档案是 `screen-learning-state-运行ID-尝试次数` artifact，内含 `state.json.gz`，保存30天，内容滚动保留最多120个观测交易日。恢复时核对仓库、main分支、每日workflow路径、事件、run ID、head SHA以及压缩大小限制；不把可被驱逐的cache当成权威历史。不把 `GITHUB_TOKEN` 转发到临时下载地址。状态损坏或来源无法核验时沿用原选股排序，不用损坏状态升级。

首次建档若仍处于同一收盘日且下一个交易日尚未开市，可从已核验的旧日报artifact引入当日技术入选、最终日报股票和发送ACK；模型否决只认原日志中的明确记录。不得在下一交易日开市后利用后续走势重建旧特征。恢复到同日记录时保留首次快照和排序，实际发送凭证只作单向补全。

学习准备阶段失败不会阻止既有选股和发送；档案上传失败会显示工作流失败，避免把未持久保存说成成功。没有历史档案时明确从首日重新积累。

## 报告与开关

每日artifact包含 `reports/screen_learning/review.html`、`review.md`、`review.json`、`context.json`、`model_audit.json`。HTML可查看逐日各持有期结果、近期上涨样本与特征对照；当前完整日尚无后续行情时明确显示待核验。

full模式的大盘复盘末尾附简短选股复盘，沿用同一条消息及原发送凭证，不增加独立飞书发送。合并通知和云文档消费的返回报告也包含同一段；stocks-only模式可在artifact查看完整复盘。

GitHub Repository Variable `SCREEN_LEARNING_ENABLED` 默认true，设false完全关闭学习建档、排序和复盘附加，不影响原选股。`SCREEN_LEARNING_CONTEXT`、`SCREEN_LEARNING_REVIEW`、`SCREEN_LEARNING_MODEL_AUDIT` 是工作流内部文件路径，不在Web设置页配置。

Actions的 `learning-only` 模式仅建档/复盘/保存档案，不运行原股票筛选和 `main.py`，不读取通知发送步骤，也不发送飞书。此模式如未成功持久保存学习档案会返回失败，不用绿色任务掩盖学习失败。

本地只读建档：

```bash
python scripts/screen_learning.py prepare
python scripts/screen_learning.py finalize
```

本地不自动读取GitHub凭证，可显式传 `--state`、`--output-dir`、`--screen`、`--audit`、`--receipt`。GitHub自动恢复artifact，本地从指定文件继续。脚本本身不调用选股分析模型、不发送消息；周末可保存最近完整收盘行情，不能在盘中冒充昨日快照。

回滚：先将 `SCREEN_LEARNING_ENABLED=false` 即可立即恢复原排序及原报告；完整回滚revert本PR，无数据库迁移、无持久股票池改写。保留学习artifact可供以后只读审计。
